Root Cause Analysis 
Storyline 
You are an ecologist working on the planet Photospheria, and your job is to build a biological 
sample from the planet’s plant life and bring it back to Earth for study. 
The plant life on Photospheria works through interaction. Different plants affect each other 
depending on where they are placed. Some combinations cause new species to appear. Other 
combinations make it more difficult for plants to flourish. Because of this, what you choose to 
place together directly shapes which kinds of plants exist in your final sample. 
Your main goal is to create the most useful possible sample for Earth’s scientists. 
Each unique species provides new information into how life functions on this planet. A more 
diverse collection offers a broader and more complete understanding of Photospherian biology. 
Therefore, your score is determined primarily by the number of different species you successfully 
cultivate and include in your final sample. 
There is also a secondary goal: longevity. 
The longer a species remains alive, the more reliable the data available for analysis back on Earth. 
Your task is simple: 
• Build the best possible sample of Photospherian plant life. 
• Maximise the diversity of species in your collection and keep them alive for as long possible. 
Fortunately, some of your ecological colleagues have gone through the trouble of creating various 
encyclopedias and notes of all the plants, animals and events you will encounter in your 
experiments. These notes, along with a deep dive of the mechanics you will work with can be found 
in the following pages. 
Problem Overview 
Basic Game Structure and Rules 
• Your garden is an 𝑁×𝑀 grid on which you can place plants. 
• Each cell (x-y coordinate location on the grid) can only contain one plant at a time, unless a 
plant's rules explicitly allow coexistence (e.g., the subsurface_growth special rule). 
• Time is discrete and represented with ticks. 
• On each tick you may choose to plant a minimum of zero and a maximum of twenty plants 
at specific coordinates within the grid. 
• Your submission will be a sequence of instructions specifying which plants to place at 
which grid points. See the Submission Format section for more details.

• Most plants are not available for planting straight away. These plants are locked behind 
unlock conditions, which must be met before you can place them. Any attempt to place a

• Different plants have different properties and spreading behaviours.

• Only the final state of your garden is used to calculate your score. See the Scoring Function

Problem Mechanics 
Grid and Time 
The garden is represented as an N × M grid. Each cell can contain a plant, subject to the game rules. 
The simulation runs for T ticks (days). On each tick, you may choose to plant one or more plants at 
specific coordinates within the grid however, you can only place one plant per cell. Participants 
must submit a solution file describing their planting actions throughout the simulation. 
Grid Layout 
The garden is represented by a coordinate system. Example: 
• Grid Width (N): 100 cells 
• Grid Height (M): 100 cells 
• Valid X coordinates: 0 - 99 
• Valid Y coordinates: 0 – 99

Ticks (Days) 
The simulation progresses in discrete time steps called ticks. Tick 1 represents Day 1. Tick T 
represents the final day. Participants may schedule planting actions on any tick from 0 (initial setup) 
to T-1, final actions occur on the penultimate day, and scoring is done on the state of the world on 
the final day. 
A planting action specifies: 
• The tick at which to place. 
• The plant index (matching the index value in the supported plant catalogue). 
• The X coordinate. 
• The Y coordinate.

Constraints 
• Coordinates must remain within the bounds of the grid. 
• Ticks must be positive integers between 0 and T-1. 
• Multiple plants may be scheduled during the same tick. 
• Plant indices must match the index values in the supported plant catalogue provided for 
the challenge. See section Plant Encyclopedia. 
• Plants with unlock conditions will only place successfully if all of their unlock conditions 
are met. 
• Plants can only be placed in soil; any other terrain type is uninhabitable. 
• Only one plant may be placed on a cell. If your action dictates that a plant must be placed 
on an occupied cell, then the existing plant on that cell will be replaced by your new plant. 
• You may only plant 20 plants per tick. Only the first 20 plants in your list for each tick will be 
planted. 
Plant Encyclopedia 
Each plant species is defined by a set of basic properties that determine how it grows, spreads, and 
competes within the ecosystem. Plants are recorded with the following basic properties: 
• Time to maturity 
The amount of time a plant requires before reaching maturity. A plant can only begin 
competing for nutrient capacity in a cell once it has matured. You can find out more about 
nutrient capacity in the Soil section below. Plants that cast shade or have area effects only 
start once they are mature. 
• Rate of spread 
How long it takes for the plant to spread to surrounding cells, measured in ticks. 
• Spread mechanism 
The method by which the plant propagates. Different spread mechanisms interact 
differently with environmental features and animal species, which may help or hinder the 
spread of the plant. 
• Spread type 
The shape or direction in which the plant propagates. Examples: Moore, Von Neumann, 
Row, Column, Cross-hatch. 
• Spread range 
How far the plant propagates in the specified pattern at each step of a spread action.

• Root type 
Shallow-root, deep-root, and none. These have an effect on unlock conditions. 
• Invasiveness hierarchy 
This rank determines which plants will outcompete the current plant. The higher the rank, 
the more plants it can outcompete. If two plants want to occupy the same cell, the one with 
a higher rank wins. 
• Weaknesses 
Specific conditions under which a plant cannot spread, thrive or survive. 
• Special rules 
Unique abilities, or behaviours associated with a plant species. 
• Preferred soil 
A plant will only spread into cells of its preferred soil. 
The full catalogue of plant species and their properties is provided in plant_dataset.json. The 
JSON schema for ingesting this data is defined in the Plant Ingestion section. 
Each plant also belongs to a classification. These classifications form part of certain unlock 
conditions and can be found in classifications.json.

• Grass

It is up to you to strategically plant these to create the conditions in Photospheria needed to plant 
more plants and unlock as many species as possible. Refer to the Plant Unlock Conditions section

Photospheria Cell Types 
Soil and cell types: 
These constitute the cells in which you will be allowed to place plants. Each plant also has 
preferred soil types it can spread into. 
Nutrient capacity is a resource that is consumed when a plant occupies a cell. Cells start with 100 
nutrient points. While a plant occupies a cell, its nutrient points decrease at a rate of 1 point per 
tick. When the cell reaches 0 points, it is no longer inhabitable and the plant dies, leaving dead 
plant matter in the cell. A cell containing dead matter regains nutrient points at a rate of 1 point per 
tick, capped at 100.

Soil is divided into the following types, identified by numeric ID: 
•  0 : Dirt 
•  1 : Mud 
•  2 : Clay 
•  3 : Burnt 
Photospheria also contains the following natural elements affecting its soil: 
• Water Feature 
Always surrounded by clay soil types. 
• Stone 
These cells are uninhabitable. Stone reeds can only sprout from cells adjacent to stone. 
• Path 
A terrain type. Plants cannot spread onto paths. 
• Cracks 
These cells form after earthquakes. New cracks may appear over time, altering the layout of 
the world. Skyvine can spread over cracks. Experiment with different submissions to gauge 
the formation of cracks due to earthquakes in the world. 
• Burnt Soil 
These cells surround Emberroot Trees. These harsh conditions make it difficult for almost 
all plants to spread into burnt soil. 
Climate, Seasons, Plant Coverage and World Events 
The world of Photospheria is subject to various environmental conditions that affect plant growth, 
spread, and survival. 
• World events 
The known world events are Rain, Drought, Ash Eclipse, and Earthquake. Natural events are 
the same as world events. These events are scheduled to occur at a specific tick, which is 
defined in the level file. They are referenced by plant unlock conditions. Example: Crystal 
Cactus requires a Drought event, Mire Bloom requires a Rain event, and Phoenix Bloom 
requires an Ash Eclipse. 
• Shade 
Certain plants cast shade, like Oak Tree, for example. Once such a plant reaches maturity, 
the cells surrounding it within a given radius are given the shaded state. The shade_radius 
special rule determines how far around the plant the shade condition extends. Shade 
prevents plants with a shade weakness (no_shade_survival, no_shade_spread) from 
spreading into a shaded cell. The adjacent_shade_penalty special rule applies when the 
plant with this rule exists on a cell that is shaded.

• Seasons 
The seasons are Spring, Summer, Autumn, and Winter. Season changes are dictated in the 
level file, which specifies the new season name and the tick on which the change occurs. 
Seasons are deterministic and only exist to activate plant-specific rules, such as 
no_winter_spread or the season_summer conditional modifier. 
• Dead matter 
Dead matter occurs in a cell where a plant has died. That is, where the cell's nutrient points 
have fallen to 0. It is represented by a state flag on the cell. When a cell contains dead 
matter, it regains nutrient points at a rate of 1 point per tick (capped at 100). If a plant 
moves into a cell containing dead matter, the cell instead loses nutrient points at a rate of 
0.5 per tick. Plants only feel the effects when nutrients are on 0 (resulting in plant death). 
• Coverage percentages 
Percentages used in unlock conditions and animal requirements refer to the total available 
cell coverage in the world. Example: "8% Coverage with Lavender" means that if the world 
had 100 cells, at least 8 of them must contain Lavender for the requirement to be met. 
Animals 
Among the plant life on Photospheria, there is an abundance of wildlife that also has a significant 
effect on how the plants grow, spread and thrive. Animals are either absent from the world or 
present. When certain conditions are met, an animal type becomes present in the world and starts 
affecting plants in certain ways. Once the conditions for a particular animal are no longer met, that 
animal will also no longer be present in your world. 
The full list of animal species, their appearance requirements, and their effects is provided in 
animals.json. The JSON schema for ingesting this data is defined in the Animal Interaction Data 
Structure section.

Level Descriptions 
Your experiments will be done in different stages to help you become familiar with certain concepts 
before scaling up into the final level. 
Level 1: Greenhouse Study 
You will grow your plants in a greenhouse to guard against animals and weather conditions 
however, seasons still apply. You will only work with a small subset of plants, and your aim is to 
grow a diverse garden. Because of the limited space, you will only be able to use a small subset of 
the plants. 
Level 2: Garden Growth Study 
Now that you have the hang of things, we will move outside into a small garden. Your plants are 
now exposed to the elements, and a few critters might come and say hi. To add to this, you also 
have a wider variety of plants available since you have more space.

3. growth (object) 
Defines all intrinsic biological and simulation-relevant growth parameters. 
"growth": { 
  "time_to_maturity": number, 
  "spread_rate": number, 
  "spread_mechanism": string, 
  "spread_type": string, 
  "spread_range": number, 
  "root_type": string, 
  "invasiveness_rank": number, 
  "conditional_modifiers": [optional array] 
} 
Field Definitions 
time_to_maturity (int) 
• Number of ticks required before the plant becomes "active". 
• Before this threshold, the plant does not spread or trigger effects. 
 
spread_rate (int) 
• The number of ticks that must pass before the plant can perform a spread action. 
• A lower value means the plant spreads more often. 
 
spread_mechanism (string) 
Defines the biological propagation mechanism. 
Typical values: 
• "Shoots" 
• "Seeds" 
• "Spores" 
• "Pollination" 
 
spread_type (string) 
Defines spatial propagation geometry. Common values: 
• "VonNeumann" → 4-directional (N, S, E, W). 
• "Moore" → 8-directional (including diagonals). 
• "Row" → linear propagation along a row axis. 
• "Column" → linear propagation along a column axis. 
• "CrossHatch" → structured multi-axis expansion pattern.

spread_range (int) 
• Determines the radius around the plant that is included in its spread_type pattern. 
 
root_type (string) 
Defines environmental dependency layer and plant interaction. Possible values: 
• "Shallow" → surface-level dependency, sensitive to immediate conditions. 
• "Deep" → stable, less sensitive, possibly stronger persistence. 
• "None" → no root dependency (fungal-like or free-floating systems). 
Used by environmental simulation layers (soil, terrain, nutrients, stability rules). 
 
invasiveness_rank (int) 
• Relative aggressiveness / ecological dominance score. 
• Higher values imply: 
o Stronger spread pressure. 
o Higher competition strength. 
o Greater ecosystem impact. 
Competition resolution 
When two plants spread into the same cell, the plant that spreads into the cell last wins — since 
neither plant has reached maturity at that point, neither can compete using its invasiveness rank. 
The plant that occupied the cell first is therefore overwritten by the next plant to spread into it. Note 
that some special cases, such as Ashroot Bramble, which only spreads on burnt soil, are 
exceptions.

Plant Unlock Condition Trees 
Most plants available in the game cannot be planted unless certain conditions are met. 
The full set of unlock conditions for every plant species is provided in 
plant_unlock_conditions.json. Each plant unlocks when its condition tree evaluates to true. 
A condition tree consists of: 
• Logical nodes (AND, OR, NOT). 
• Leaf condition nodes (coverage checks, species checks, events, counts, etc.). 
Logical Nodes 
AND 
All child conditions must be true. 
{ 
  "op": "AND", 
  "children": [ 
    { ... }, 
    { ... } 
  ] 
} 
OR 
At least one child condition must be true. 
{ 
  "op": "OR", 
  "children": [ 
    { ... }, 
    { ... } 
  ] 
} 
NOT 
The child condition must be false. 
{ 
  "op": "NOT", 
  "child": { ... } 
}

Animal Interaction Data Structure 
The data can be found in animals.json. 
Each animal is represented as a structured rule object consisting of: 
• id: Unique name. 
• requirements: A boolean tree of conditions (AND/OR nodes). 
• effects: A list of modifiers applied when requirements are satisfied. 
Core Schema 
Each animal follows this structure: 
{ 
  "id": "string", 
  "name": "string", 
  "requirements": { 
    "type": "AND | OR | CONDITION", 
    "conditions": [] 
  }, 
  "effects": [ 
    { 
      "type": "string", 
      "target": "string", 
      "value": "number | string", 
      "mode": "add | multiply | set" 
    } 
  ] 
}
